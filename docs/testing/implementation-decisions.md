# Implementation decisions

Chronological controller rulings and their recorded costs, retained verbatim from the implementation ledger. Final refresh occurs before controller-owned scratch cleanup.

1. Ruling: Use ReceiptImportService.importReceipt rather than import — import is a reserved Dart keyword; receipt semantics stay unchanged — cost if wrong: update method call sites/fixtures, no data-format change.

2. Ruling: SessionHandle is an opaque abstract interface; local IdentityService issues a private implementation and authorizes only exact live-registry object identity — core cannot privately construct adapter-owned sessions across Dart libraries — cost if wrong: unauthorized instances could pass if a later service checks only type, so Task 2 must test forged/stale handles.

3. Ruling: Resolve Drift/drift_dev at 2.34.0 and build_runner at 2.15.1 — original pins conflict with installed Flutter test/analyzer constraints; actual pub solve uses analyzer 12.1.0/build 4.0.7 — cost if wrong: generator/API upgrade work later; lockfile and native builds validate current compatibility.

4. Ruling: Personal snapshots use explicit durable person-to-record associations while retaining original company IDs; all snapshot sections are scoped, and identity metadata is composed from the separate profile catalog — opaque payloads cannot safely infer ownership — cost if wrong: association/schema migration and archive scope adjustments, never a blanket company export.

5. Ruling: Add repository prepare/pendingOperations APIs alongside commit to durably queue operation IDs/digests before execution — required process-death retry cannot live only in memory — cost if wrong: update queued-command callers and recovery fixtures; wire format unaffected.

6. Ruling: Use dart run build_runner build without removed --delete-conflicting-outputs flag — resolved build_runner reports it ignored and output reproduces identically — cost if wrong: adjust generator invocation on future toolchain change; no data/schema change.

7. Ruling: Separate snapshot logical-item limits from ZIP file-entry limits: snapshot maxEntries default/hard ceiling524,288 (64MiB/128-byte minimum item charge), still bounded by maxBytes≤64MiB; each owner link costs128+UTF8 ID bytes; ZIP cap remains10,000 — reusing ZIP cap for rows prevents required100staff/10,000event fixture — cost if wrong: tune snapshot memory budget/API after measurement; archive v1 file limit stays unchanged.

8. Ruling: Company creation reserves a random UUIDv4 company ID durably against personId+operationId+normalized intent before provisioning — deterministic UUID-shaped hashes violate the established ID contract and fresh random IDs duplicate retry creations — cost if wrong: migrate bootstrap reservation/API and restore treatment.

9. Ruling: Add routing-only company discovery with all visibility filtered by service membership/restricted session; issue operator handles through local identity extension with explicit company restriction — existing repository/session contracts lack discovery and operator issuance — cost if wrong: revise discovery/operator interfaces and re-audit every permission boundary.

10. Ruling: Add synchronous repository commit authorization guard after all awaited mutation/journal/checkpoint work and before commit dispatch; validate replay disclosure after decrypt — session may expire during asynchronous cipher/storage work — guard defines acceptance boundary: earlier lock rolls back, later lock invalidates session/UI without falsely rejecting committed data — cost if wrong: revise service guard integration and UI result reconciliation; SQL commit cannot be canceled retroactively.

11. Ruling: Non-owner management capabilities require an activated company-restricted operator session; grant alone does not let a personal-profile session manage that company — v1 management operators use separate company-bound credentials on management device — owner personal sessions and staff own-membership/attendance remain valid — cost if wrong: change permission/UI policy and credential activation UX, while retaining cross-company isolation.

12. Ruling: Wire keyId is ed25519: plus unpadded base64url(SHA256(raw32-byte public key)), exactly51ASCII bytes, required to match verification key for every message; local signing:/operator-signing:/company-root: IDs stay internal — signature domain excludes outer keyId, so deriving it prevents unauthenticated aliases even on self-signed requests — cost if wrong: change unreleased message fixtures/builders/trust indexing or version protocol after external use; local stored identities remain intact.

13. Ruling: v1 text limits count Unicode scalars; UTC milliseconds use representable range±8640000000000000, revision/sequence1..9007199254740991, valid IANA IDs max120scalars; grant label120 and invitation40; payload public keys/signatures use canonical padded base64url matching existing authority bytes — strict parser needs explicit interoperable bounds — cost if wrong: adjust fixtures/validators and version published wire format if compatibility changes.

14. Ruling: Add a separate versioned public .razecheck-history JSON artifact with exact grammar/bounds and transactional history-only import defined in Task11brief; existing eleven message kinds stay unchanged — single embedded certificates cannot bridge a staff device offline across multiple lost-source recoveries, and private owner archives are inappropriate staff transport — cost if wrong: revise the unreleased history-file grammar/UI or version it after publication; preserve pinned-root/lineage/fork safeguards and no capability activation.

15. Ruling: Pin direct archive dependency4.5.2 instead of plan4.0.9 — currently locked image4.12.0 requires archive^4.5.0; retaining already resolved compatible graph avoids unrelated downgrades — cost if wrong: adjust archive adapter/pin and rerun format/security fixtures; archive wire grammar unchanged.

16. Ruling: Personal archive recovery carries authenticated passive person/profile/public installation history, not old device signing seeds or unlock verifiers; fresh local credentials preserve person ID in Task11, then manager return grants gate staff activity — no existing portable personal recovery key exists and copying active device credentials violates the spec — cost if wrong: revise inner recovery schema and identity activation UX before public archive compatibility commitment.

17. Ruling: Extend Mutation with company-scoped atomic personal-association removal before reassignment during explicit manual staff linking — retaining placeholder ownership would leak the enrolled person's records through a former personal scope — cost if wrong: revise repository mutation/import sidecar handling and downstream restore tests; employee/membership and signed-message IDs remain stable.

18. Ruling: Extend explicit invitation consent with session-bound staged candidate-root/full-history verification before atomic first pin, retaining ban on standalone unpinned history trust; separate accepted lineage/staff remote issuer knowledge/local management activation — new staff at a later generation otherwise faces a circular missing-parent-versus-required-pin dead end — cost if wrong: revise onboarding staging/state APIs and recovery tests; no existing signed-message/history-file grammar change or permission shortcut.

19. Ruling: Keep new manual punches as auditable locally held records/report/scoped archive data; v1 return acknowledgments/decisions update only known authenticated staff receipts and never create unknown manual events — existing exact wire types lack manual source/subject transport and approved Task8 does not require that separate delivery — cost if wrong: add a reviewed versioned manual-record transfer later; UI must disclose this offline delivery limit without faking staff signatures.

20. Ruling: Amend unreleased v1 attendanceDecision with independent correction request/outcome fields and pending attendance projection only for corrections; direct manager correction command preserves review state, explicit review alone changes it — original single outcome conflates rejected correction with rejected attendance, cannot correlate requests or represent required direct manager correction, and later decisions must retain current effective fields — cost if wrong: revise strict schemas/fixtures/protocol and consumers before distribution, or version the wire format if already external; no old signed attendance receipt changes. Exact grammar/conditional rules in Task8brief/global-context.

21. Ruling: Allow records.json up to64MiB within unchanged64MiB total expanded/encrypted archive limits; all other entries retain8MiB and ZIP10000 cap — measured existing fixture lower bound for10000 original transports alone exceeds8MiB, so earlier preserve8MiB guidance conflicts with engineering acceptance — cost if wrong: tighten implementation limits or revise archive version/streaming strategy after actual memory/performance measurement; full10000-event backup is not yet proven to fit total64MiB.

22. Ruling: Use owned bounded Android/iOS document selection/staging bridges instead of file_selector's pre-Dart full-buffer/materialization behavior; add PNG/JPEG8192-edge/16,777,216-pixel guard alongside20MiB — inspected pinned native Android source allocates whole provider size before Dart validation, and byte size alone cannot bound raster allocation — cost if wrong: maintain extra native adapter code or adjust verified image limits; legitimate larger photos require cropping, and external provider materialization remains outside app control. Exact implementation/test boundary in Task9brief.

23. Ruling: Use an explicitly documented versioned exact-byte content-addressed payload/identifier table inside records.json, with complete row/operation/result/journal/ownership references, and a repository-owned consistent bounded export traversal; retain materialized snapshot and archive64MiB limits, cap referenced logical payload expansion at64MiB and logical items at524288 — direct encoding and materialized snapshot admission cannot fit the required realistic10k import fixture, while exact deduplication can plausibly fit without omitting history — cost if wrong: revise unreleased inner archive schema/traversal or report measured capacity gate; full crypto/JSON memory remains bounded by inputs but is not genuinely streaming or proven safe on all devices.

24. Ruling: The100staff/10000event performance archive is the complete manager store importing externally captured staff receipts, including every locally retained setup/operation/result/journal/association and any exercised decisions; separate staff capture stores remain separate, with whole manager backup measured — this matches normal offline delivery and avoids inventing manager-local capture drafts; reviewed-all10k or combined-capture/import capacity is not promised — cost if wrong: expand the fixture/capacity design and repeat device measurements; any actual overflow remains an explicit failed acceptance gate, never a subset or truncation passed as full backup.

25. Ruling: Archive device-local operator credentials as explicit retired public metadata and replay-blocking operation tombstones, preserving operation IDs/revisions/authority and journal associations while excluding verifier/salt/local signing refs and password-derived request digests — exact credential/result export would transplant reusable local secrets, while deleting operations/journals violates provenance; activateOperator digest itself commits quickly to the passphrase — cost if wrong: revise portable tombstone/schema/merge handling and require operator re-setup; ordinary noncredential records/results remain exact, and no old operation may reactivate a credential.

26. Ruling: Attendance report calendar filters use current effective punch time in the company time zone, with inclusive selected dates implemented as a half-open local-calendar interval; retain original claimed/received times and correction history columns and label the filter — corrected attendance should appear on its corrected work date while original evidence remains inspectable, and neither spec nor plan names an axis — cost if wrong: add or switch an explicit original-date filter and revise report fixtures/UI; immutable receipts and historical decisions remain unchanged.

27. Ruling: Failed restore retains completely published immutable attachments and newly allocated scope vault keys required to decrypt them, while rolling back DB/profile/gate changes and cleaning owned staging/journals/unrelated new keys; retries validate and reuse identical content — a concurrent legitimate attachment writer can already reference a published object, so rollback deletion violates the immutable-store contract — cost if wrong: encrypted orphan files/keys consume storage until a future lease/reference-aware garbage collector; no active identity or successful restore is implied, and source/prior data remain intact.

28. Ruling: Once restore publishes a newly allocated shared scope vault key, rollback retains it even when no restore-owned attachment move is recorded; cleanup still removes private staging keys and proven-owned unrelated recovery allocations — normal attachment/record writers can use the shared vault before or between existence checks, so ownership alone cannot prove the key is unused without a lease protocol — cost if wrong: additional unused encrypted-scope keys persist until coordinated garbage collection, but concurrent data cannot be rendered unreadable by rollback.

29. Ruling: Recover an original person through an opaque pending identity/key draft, activated only by an exact manager replacement grant or same-person owner recovery/handover; enforce company-specific installation authorization for reads, exports, writes and replays after adoption — existing person-ID-only checks predate identity adoption and an employer grant must not unlock another company — cost if wrong: revise recovery APIs, authorization migration and tests; pending/public identifiers alone never grant ordinary access and unrelated profiles are never renamed or merged.

30. Ruling: Add a narrowly authorized selected-company staff recovery archive export bound to the exact approved replacement request/grant, requiring manageMemberships and exportAttendance; preserve ordinary personal export as self-only — staff without a personal backup must recover manager-received records without receiving company recovery secrets or another company’s data — cost if wrong: revise the recovery projection/UI and permission combination; only explicitly associated staff data/public dependencies travel, and lost unsent records remain unavailable.

31. Ruling: Extend handover begin with a transient archive passphrase; recover consumes a live authenticated company preview plus explicit checkpoint/missing-data confirmation instead of an undefined recoverySecret; transfer/ack snapshot hashes are SHA-256 of exact authenticated manifest.json bytes — final encrypted export needs passphrase input, Task10 already verifies root recovery material, and the manifest binds all archive contents after the selected file is released — cost if wrong: revise unreleased service APIs and protocol digest semantics before external use; no wire fields change or passphrase persistence is permitted.

32. Ruling: Owner-target replacement requests with null employee ID use only the session-bound pending candidate/root consent and do not persist an invitation pin or company operation before company snapshot restoration; activation verifies the exact offered source and full authority chain against the authenticated company preview and same consent — preliminary pin revision1 collides with preserved company snapshot revision1, and a self-signed request is only a claim, not access — cost if wrong: revise owner bootstrap ordering/consent binding and recovery tests; null employee ID never grants owner authority or bypasses staff replacement authorization.

33. Ruling: A pending staff replacement for an authenticated personal restore may use that exact original-person/company/root public trust and full accepted lineage as candidate-only context without a setup-profile pin or journal write; explicitly consented newer invitation lineage stays staged until exact replacement-grant activation publishes necessary trust atomically — pinning before restore collides with preserved revision history and pinning after restore violates its passive gate — cost if wrong: revise pending restoration/activation ordering and consent bindings; archive possession and public lineage alone never activate a person, company access, or management, and the grant must still bind the exact fresh key/request.

34. Ruling: Support successive company recovery through an opaque continuation draft bound to the already unlocked original-person profile and its current installation/key, adding only the explicitly authorized company after its exact replacement grant or same-person owner recovery proof — permanent profile-collision rejection, though allowed as the safe initial default, leaves approved multi-company device recovery incomplete — cost if wrong: revise continuation/journal APIs and tests; it must never rotate existing company keys, merge unrelated profiles, replace existing credentials, or expand access without the second company’s proof.

35. Ruling: Authenticated restores may merge passive public profile metadata for the exact same person by unioning public installation-ID/key pairs and retaining existing descriptive metadata; same installation ID with a different key still rejects — independently scoped staff and owner archives legitimately contain different subsets of that person’s public device history and names, so byte-equality blocks approved mixed-role recovery — cost if wrong: revise passive metadata merge/export compatibility and tests; descriptive metadata may remain older, while active credentials, permissions, signed evidence and company authority remain untouched.

36. Ruling: Complete the explicitly required Task11 integration combinations during its review fix round: returning staff across at least three actual authority transitions including lost-source recovery without an intermediate message, complete new G3 enrollment, and bounded multi-batch invitation staging with its stated invalidation cases — the review labels M1 Minor, but the brief explicitly requires these integration proofs and isolated certificate tests do not establish them — cost if wrong: additional focused real-service test runtime and fixture maintenance; no product or protocol scope expands.

37. Ruling: Keep missing-catalog-key recovery fail-closed and preserve all ciphertext; complete Task13 with explicit external-archive recovery on a fresh usable installation, and explain that route and the current same-install limitation in the recovery-required UI and documentation — the approved plan forbids silently replacing keys, specifies portable archives and clean-install recovery, and does not require a new sessionless reset/quarantine subsystem — cost if wrong: a future in-place recovery workflow and additional UX work; permanent key loss remains unrecoverable without valid external recovery material, and temporary secure-store failure must retain a distinct retry message.

38. Ruling: Let the full capacity baseline continue unchanged and run other Flutter/device gates from an owned disposable source/build copy with fresh generated directories and recorded exact source hashes — the measured import slowdown has no specified latency SLA, while concurrent Flutter tools in one workspace previously collided and a new lookup subsystem would add unproven scope — cost if wrong: extra disk/build time and reconciliation work; results must name their source snapshot and be rerun after relevant code changes, and neither synthetic user data nor historical device keychains may be copied into that build workspace.

39. Ruling: Retain early capacity timing checkpoints as timing-only and obtain detailed SQL/AES/byte/concurrency measurements from consistent diagnostic copies at explicitly recorded actual larger checkpoints, including the completed target when available — the already-running baseline omitted query instrumentation and its remote signer seeds are process-only, while an online SQLite backup plus synthetic test keys allows an independent real-service probe without changing or restarting that baseline — cost if wrong: early scale attribution remains unmeasured and diagnostic imports add one clearly counted signer; do not claim the probe is the original import sample or a second full capacity pass, and preserve all baseline records in every diagnostic copy.

40. Ruling: Permit an independent Task13 review of a committed finished-source/device-evidence checkpoint while its unchanged long capacity run continues; leave Task13 incomplete, then review every later source/evidence delta and resolve all pending acceptance obligations before task completion or final whole-branch review — the plan permits review of finished work in parallel, no production feature work remains, and severe external host pressure makes waiting on the baseline costly without helping review — cost if wrong: an additional scoped review/reconciliation pass; a checkpoint approval must never be presented as capacity, final-build, task-completion, or release approval.
