# Physical process-death acceptance

The reproducible entrypoint is `integration_test/process_recovery_test.dart`. It requires a unique `RAZE_PROCESS_RUN` (8–80 alphanumeric/hyphen characters) and `RAZE_PROCESS_CASE=before|committed|visible`. Keep the exact compiled artifact through both launches. The first launch deliberately waits for real host termination and cannot produce a passing driver result. A timeout is a failure, not evidence of a kill.

This harness uses two independently enrolled logical stores with actual OS secure keys on one phone. It does **not** establish two-phone enrollment or a printed workplace camera scan. Those remain separate operator gates. No app data clearing, Keychain clearing, hot restart or graceful repository close substitutes for OS termination.

1. Recheck target installation ownership and ensure the phone is available. Do not replace or interrupt another user's app/data. Record platform/OS, source revision, compiled entrypoint, compile-time flags and artifact hash privately. Use only disposable test installs. For iOS prebuilt drive use `--keep-app-running` because default drive cleanup can uninstall the app.
2. Build the entrypoint with a new run and chosen case. The app writes only `raze_check/acceptance/process-<run>/` below application support and secure keys prefixed `acceptance:process-<run>:`. It creates real manager/staff profiles, invitation/grant/workplace and a persisted capture draft.
3. Wait for `run.json` phase `armed`. Retrieve `run.json`, `pre.json`, and `visible.png` when the case is visible, **before** killing. The before case holds after the real mutation builder, before returning any mutation for SQL writes. The committed case holds after the real `Committed` service result, before exposing a receipt. The visible case asserts the actual receipt screen's saved label and captures that rendered frame. These are different evidence claims.
4. Record the owned app PID, terminate that exact application and verify the old PID is absent. Android: `adb -s <selector> shell am force-stop com.remyo.razecheck`. iOS: `xcrun devicectl device process terminate --device <selector> --pid <verified-pid> --kill`. No generic process-name killing. With the current Flutter iOS Debug driver, close only the exact run-owned driver/debugger session before sending CoreDevice SIGKILL: LLDB otherwise intercepts the signal and leaves the target stopped. Closing that debugger alone is not proof of termination; independently observe the target PID absent.
5. Relaunch the same installed artifact without reinstalling/resetting. Android: launch the verified manifest activity with `am start -W`. iOS: use a supported debugger/JIT launch for Debug; a plain icon tap/devicectl launch is not guaranteed to support Flutter Debug JIT. The tested iOS sequence is `devicectl device process launch --start-stopped`, import the generated Flutter LLDB helper before attaching, select the exact device, attach to the returned fresh PID, wait for that PID’s stopped/SIGSTOP event, then send one `process continue`. CoreDevice attach command return alone does not establish attachment completion. Preserve the same installed executable URL and verify no post artifact predates relaunch. Missing debugger/permission support is a gate, not permission to alter settings.
6. The entrypoint opens the existing run, unlocks the exact stored staff identity through real KDF, verifies the original operation/event IDs and original transport/payload bytes, and checks exactly one event/outbox. For before-commit it first checks zero event/outbox and the same pending operation, then retries to one complete result. Both committed cases reopen the saved receipt and replay it without a new event. It writes `post.json` and marks the run complete. An existing non-armed run is rejected rather than overwritten.
7. Retrieve only the known test reports. Create private host evidence JSON containing `run`, `case`, `oldPid`, `newPid`, `killSucceeded`, `oldPidAbsent`, `noReinstallBetweenKillAndRelaunch`, `platform`, `build`, `date`, from observed commands. Run `python3 tool/compare_process_evidence.py <pre.json> <post.json> <host.json>`. Preserve its sanitized result and the exact synthetic bytes/screenshots. Device selectors, provisioning names, VM-service tokens and whole containers are not report artifacts.

Android reports can be retrieved with `adb exec-out run-as com.remyo.razecheck cat <known-relative-path>`. iOS uses `devicectl device copy from --domain-type appDataContainer --domain-identifier com.remyo.razecheck --source <known-relative-path> --destination <owned-host-file>`. Discover the exact platform application-support-relative path from the owned run, not by copying the entire container. Missing report retrieval or post evidence fails the case.

The harness's fixed business clock prevents a synthetic overnight fixture from expiring its own profile; host wall-clock deadlines and PID evidence establish process timing. It tests process termination, not physical power loss. Uninstall/reinstall, real external backup persistence, device lock/key availability, real camera/provider/share and unavailable minimum-OS combinations remain separately recorded in the device matrix.
